# 安全模型

## 信任边界

桥在 Host 进程内运行，持有 sessionController 能力。Bearer 持有人可委派有开发能力的 Agent；**白名单不是容器/OS 沙箱，也不是多租户授权系统**。同 Host 的其他插件、Agent 工具、终端和任务输出属于独立信任面。不要以工具 annotations 的 destructiveHint=false 推导「任务绝不会改文件」。

## 网络与认证

- 仅允许 loopback 字面量（127/8 或 ::1）绑定，默认 127.0.0.1:17300；不挂 Web 业务路由，禁止公网反代。
- 远程仅 SSH 本地转发，两端 loopback；本地其他不受信任进程也可能接触端口，仍必须鉴权并隔离系统用户。
- Authorization Bearer，先 SHA-256 再 timingSafeEqual；不复用浏览器 cookie、网页登录 session 或 GitHub token。
- 启动 secret 缺失、为空或过短则不监听；运行中每次读取当前 secret，读取失败返回 401。默认最少32字节；运维者应生成至少32随机字节，不要降到配置允许的最小值。
- 文件 600 / 父目录 700 是**运维要求**，不是本版本自动强制检查。文件修改后下次请求生效；分发与撤销由运维者负责。
- 非 loopback Origin 或非法 Origin 返回 403；无 Origin 的原生客户端可正常工作。Origin 检查不是完整浏览器/反代理安全方案；本版本未额外校验 Host 头，切勿暴露到不可信网络。

## 文件和会话范围

- cwd 必须在显式白名单根内；根路径会 canonicalize，失效根被剔除，无可用根则不启动。按 sessionId 操作仍重新检查 cwd。
- 文件工具只接受 cwd 下的相对路径，拒绝绝对路径、NUL、目录外 `..` 穿越和符号链接逃逸；目录内 `a/../b` 这种未逃逸规范化路径并非一概禁止。
- realpath 检查不是恶意并发替换文件的完整 TOCTOU 防护。不要让不可信系统用户并发控制白名单目录；需强隔离时用独立低权限 Host/容器。
- **没有敏感文件名拒绝清单**。白名单内的凭据也可能被读到；不要将家目录、凭据目录、整个服务器根设为白名单。glob 隐藏/裁剪不是保密机制。

## 行为、日志与限额

桥本身不写 git，不执行部署/重启，不记 prompt 正文和文件内容。它仅把调用转给 Host，但 Host Agent 可按任务执行命令、修改代码、访问它本来拥有的权限。因此「不合并/不部署」必须同时落实在 Host 权限、任务书和人工验收中。

日志主要是工具名、耗时、结果码；Host 错误经长度/换行裁剪后可能带路径或其他上下文，**不是通用敏感信息清洗器**。状态 queue.textPreview、投影、事件、文件和错误返回可能包含任务正文/交付物，客户端必须按敏感数据保护。不应上传原始 payload 诊断日志。

默认 prompt/steer 共享30次/分钟，全部工具共享240次/分钟，桥进程内全局计算，重启清空。follow schema与handler限制≤30s、≤200事件（Host stream必须配合AbortSignal；不是强杀机制）；maxBodyBytes 默认1MiB。这些是资源保护，不是完整防 DoS 或费用预算；高并发/恶意 Host stream 需额外隔离和监控。

## 发布前检查

离线单测不能证明真实 Host、客户端、SSH、systemd 配置安全。发布者需在隔离 Host 验证实际插件装载、权限、监听地址、鉴权失败闭、工作区侧栏绑定与短任务往返；审查项目所有示例、打包清单和许可证归属。报告漏洞见根 SECURITY.md。
